# 架构审查检查清单

按维度扫一遍。不是每项都必须写进报告，只记录有证据的发现。

## 1. 组件封装

### 前端（Vue SFC）

- [ ] 单一职责：展示 / 容器 / 表单 是否混杂
- [ ] Props 最小化且类型语义清晰（避免 `options` 大杂烩无文档）
- [ ] Emits 命名稳定（`update:modelValue`、`select`、`change` 等约定一致）
- [ ] 不 mutate props；列表项用 key 且稳定
- [ ] 插槽是否该用却硬编码；或过度 slot 化
- [ ] 副作用（请求、toast、router）是否下沉到纯 UI 组件
- [ ] `v-model` 双向是否必要；能否单向数据流
- [ ] 样式是否泄漏全局；是否依赖脆弱的深层选择器

### 后端（Controller / Service）

- [ ] Controller 是否变「胖 Service」
- [ ] Service 是否直接拼 HTTP 响应细节
- [ ] 公共校验/映射是否重复拷贝
- [ ] 模块边界：风格 / 漫画 / 章节 / 图片 是否互相硬耦合

## 2. 设计模式

- [ ] 分层是否被穿透（View 直连深层细节、Controller 直操作 SQL）
- [ ] 策略/注册表（如 AI provider）扩展是否开放封闭
- [ ] 配置 vs 硬编码：魔法字符串、重复枚举
- [ ] 状态机/流程步骤是否用 ad-hoc 布尔旗标堆叠
- [ ] 是否存在：
  - God Object（一个文件包办一切）
  - Shotgun Surgery（改一个字段散落 N 处且无共享）
  - Premature Abstraction（一次使用却三层抽象）
  - Copy-paste 变体（短篇/长篇/章节三套近乎相同逻辑）

## 3. 前端组件抽离

- [ ] 多页面重复的卡片/选择器/空状态是否共享
- [ ] `views/*` 是否塞满可抽离的区块
- [ ] `components/style`、`components/business`、`components/base` 边界是否清晰
- [ ] 抽离后是否仍需要父级注入过多 props（味道：该用 provide/composables/store）
- [ ] Admin 与 User 是否错误共享了不该共享的重型组件（或相反，该共享却复制）
- [ ] Wizard 步骤组件是否只关心本步，还是偷改全局 wizard 状态无约定

## 4. 数据流动

### 前端

- [ ] 数据来源唯一：API → Store 或 页面 state，避免双写
- [ ] Pinia：action 写异步、getter 派生；组件不散落相同 transform
- [ ] 选择器选中值：id 还是整对象？跨页面回显是否丢字段
- [ ] 乐观更新 / 加载 / 错误状态是否完整
- [ ] 事件链是否过长：A emit → B 转发 → C 再转发（中间人过多）

### 后端

- [ ] 请求 DTO → 领域字段 → 响应 DTO 映射是否清晰
- [ ] 外键/可空（如 `style_preset_id`）在 create/update/unbind 路径是否一致
- [ ] 冗余快照字段（如 `style_prompt`）与引用字段的写入时机
- [ ] 生图链路：文本 prompt + 参考图列表的组装点是否单一
- [ ] 迁移/种子：幂等？是否破坏用户数据？

### 契约

- [ ] 前后端字段名一致（snake_case vs camelCase 转换是否集中）
- [ ] 错误响应形状一致
- [ ] 图片 URL 类型白名单与落盘路径一致

## 5. 最佳实践

### 通用

- [ ] 命名可读（禁无意义缩写）
- [ ] 错误可观测（日志含关键 id，不吞异常）
- [ ] 无密钥/敏感信息进 diff
- [ ] 变更与需求/ plan 对齐；偏离有说明

### 本仓库约束对照

- [ ] 数据库：ALTER 增量、幂等迁移；禁止删库
- [ ] 不删除用户生成内容
- [ ] 前端设计质量（复杂 UI 应体现结构，而非堆控件）
- [ ] 不引入不必要依赖

### 性能与 UX（有证据再报）

- [ ] 列表无脑全量重渲染
- [ ] 大图无懒加载/尺寸控制
- [ ] 重复请求（同屏多个组件各自 fetch 全量预设）

### 安全

- [ ] 管理端接口是否鉴权/admin
- [ ] 文件类型路径是否可穿越
- [ ] 用户可控 prompt 注入到系统提示时的边界（如有）

## 审查输出自检

- [ ] 每个问题都有文件:行号
- [ ] 区分本次引入 vs 预存在
- [ ] 建议可执行且优先最小改动
- [ ] 五维都有文字，即使某维「无问题」也要写一句结论
- [ ] Top 优先级不超过 7 条（完整表可更长）
